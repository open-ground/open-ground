# 1. 项目概览

## 1.1 是什么

**Open Ground** 是一个轻量级 Java 后端基础工具包，提供企业级应用开发所需的通用基础设施：统一响应、加解密工具、操作日志框架、序列号生成、多数据源管理、对象存储、Excel 导入导出、鉴权安全、分布式批处理调度等。

- **技术栈**：JDK 17 + Spring Boot 3.x + MyBatis-Plus + Druid + Redis

## 1.2 模块体系

```

├── open-ground-dependency (pom)                    BOM 版本管理

│   ├── open-ground-common-api (jar)                SPI 接口 / 注解（零 Spring 依赖）

│   └── open-ground-common-springcloud (jar)        Feign 远程 SPI 实现
├── open-ground-security (pom)                      认证安全聚合
│   ├── open-ground-security-api (jar)              认证 SPI 接口
```

## 1.4 版本约定

- 框架版本通过 `${revision}` 统一管理（当前 `1.0.4`），所有模块使用同一个版本号
- 第三方依赖版本统一在 `open-ground-dependency` BOM 中管理
- 业务项目导入此 BOM 即可锁定全部版本，无需自行管理第三方库版本

# 2. 快速开始

## 2.1 在新项目中引入 open-ground

### 2.1.1 添加 BOM 管理

在业务项目的 `pom.xml` 中添加：

```xml
<properties>
    <open-ground.version>1.0.4</open-ground.version>
    <java.version>17</java.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>io.github.open-ground</groupId>
            <artifactId>open-ground-dependency</artifactId>
            <version>${open-ground.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

### 2.1.2 按需选择 Starter

框架提供 5 个 Starter，从轻到重按需选择：

| Starter | 包含能力 | 适用场景 |
|---------|---------|---------|
| `starter-base` | Web + MyBatis + Redis + 统一响应 DTO + 工具类 + 加密工具 + SpringDoc + PageHelper | 简单的 CRUD 微服务 |
| `starter-common` | 以上 + 操作日志 + Excel 导入导出 + OSS 对象存储 + 多数据源 + 序列号生成 + DB-Check | 需要完整框架能力的业务服务 |
| `starter-security` | 以上 + Token 鉴权 + 会话管理 + API Key + 请求加解密 + SQL 注入拦截 | 需要认证安全的服务 |
| `starter-springcloud` | 以上 + Nacos + Feign + 负载均衡（微服务模式） | 微服务架构下的业务服务 |
| `starter-all` | 以上全部能力 | 全量引入（兼容旧项目） |

以最常见的微服务项目为例：

```xml
<!-- 引入微服务 Starter，type=pom 表示 BOM 式传递依赖 -->
<dependency>
    <groupId>io.github.open-ground</groupId>
    <artifactId>open-ground-starter-springcloud</artifactId>
    <type>pom</type>
</dependency>
```

如果只需要最基础的能力（无安全、无微服务）：

```xml
<dependency>
    <groupId>io.github.open-ground</groupId>
    <artifactId>open-ground-starter-base</artifactId>
    <type>pom</type>
</dependency>
```

### 2.2.3 创建 Mapper

继承 MyBatis-Plus 的 `BaseMapper` 获得通用 CRUD，同时可定义自定义查询方法：

```java
package com.example.demo.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.example.demo.domain.entity.PubCategoryDO;
import com.example.demo.domain.entity.PubCategoryExtDO;
import org.apache.ibatis.annotations.Mapper;

import java.util.List;

@Mapper
public interface PubCategoryMapper extends BaseMapper<PubCategoryDO> {
    /** 自定义扩展查询 */
    List<PubCategoryDO> selectListExt(PubCategoryExtDO record);
    /** 树形查询 */
    List<PubCategoryExtDO> selectTreeList(PubCategoryExtDO record);
}
```

### 2.2.4 创建 MyBatis XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.demo.mapper.PubCategoryMapper">

    <resultMap id="BaseResultMap" type="com.example.demo.domain.entity.PubCategoryDO">
        <id column="INTERNAL_KEY" property="internalKey"/>
        <result column="CATEGORY_CODE" property="categoryCode"/>
        <result column="CATEGORY_NAME" property="categoryName"/>
        <result column="PARENT_CODE" property="parentCode"/>
        <result column="SORT_ORDER" property="sortOrder"/>
        <result column="SOURCE_TYPE" property="sourceType"/>
        <result column="PROJECT_ID" property="projectId"/>
        <result column="COMPANY" property="company"/>
        <result column="CREATE_USER" property="createUser"/>
        <result column="GMT_CREATE" property="gmtCreate"/>
        <result column="UPDATE_USER" property="updateUser"/>
        <result column="GMT_MODIFY" property="gmtModify"/>
        <result column="DEL_FLAG" property="delFlag"/>
    </resultMap>

    <resultMap id="ExtResultMap" type="com.example.demo.domain.entity.PubCategoryExtDO"
               extends="BaseResultMap">
        <collection property="children" column="CATEGORY_CODE"
                    select="selectTreeList"
                    ofType="com.example.demo.domain.entity.PubCategoryExtDO"/>
    </resultMap>

    <sql id="Base_Column_List">
        INTERNAL_KEY, CATEGORY_CODE, CATEGORY_NAME, PARENT_CODE, SORT_ORDER,
        SOURCE_TYPE, PROJECT_ID, COMPANY, CREATE_USER, GMT_CREATE,
        UPDATE_USER, GMT_MODIFY, DEL_FLAG
    </sql>

    <select id="selectTreeList" resultMap="ExtResultMap">
        SELECT <include refid="Base_Column_List"/>
        FROM PUB_CATEGORY
        WHERE DEL_FLAG = '0'
        <if test="parentCode != null">
            AND PARENT_CODE = #{parentCode}
        </if>
    </select>

    <select id="selectListExt" resultMap="BaseResultMap">
        SELECT <include refid="Base_Column_List"/>
        FROM PUB_CATEGORY
        WHERE DEL_FLAG = '0'
        <if test="categoryName != null and categoryName != ''">
            AND CATEGORY_NAME LIKE CONCAT('%', #{categoryName}, '%')
        </if>
        <if test="sourceType != null and sourceType != ''">
            AND SOURCE_TYPE = #{sourceType}
        </if>
    </select>
</mapper>
```

### 2.2.5 创建 Service

**接口：**

```java
package com.example.demo.service;

import com.example.demo.domain.dto.PubCategoryCreateRequest;
import com.example.demo.domain.dto.PubCategoryQueryRequest;
import com.example.demo.domain.dto.PubCategoryUpdateRequest;
import com.example.demo.domain.dto.PubCategoryDeleteRequest;
import com.example.demo.domain.entity.PubCategoryDO;

import java.util.List;

public interface PubCategoryService {
    List<PubCategoryDO> query(PubCategoryQueryRequest request);
    void create(PubCategoryCreateRequest request);
    void update(PubCategoryUpdateRequest request);
    void delete(PubCategoryDeleteRequest request);

```

**实现：**

```java
package com.example.demo.service.impl;

import com.example.demo.domain.dto.PubCategoryCreateRequest;
import com.example.demo.domain.dto.PubCategoryQueryRequest;
import com.example.demo.domain.entity.PubCategoryDO;
import com.example.demo.domain.entity.PubCategoryExtDO;
import com.example.demo.mapper.PubCategoryMapper;
import com.example.demo.service.PubCategoryService;
import io.github.openground.base.exception.CommonException;
import io.github.openground.common.keygen.KeyGenerator;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.Date;
import java.util.List;

@Service
@Slf4j
public class PubCategoryServiceImpl implements PubCategoryService {

    @Autowired
    private PubCategoryMapper pubCategoryMapper;

    @Override
    public List<PubCategoryDO> query(PubCategoryQueryRequest request) {
        PubCategoryExtDO query = new PubCategoryExtDO();
        query.setCategoryName(request.getCategoryName());
        query.setSourceType(request.getSourceType());
        return pubCategoryMapper.selectListExt(query);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void create(PubCategoryCreateRequest request) {
        // 1. 业务校验：检查名称是否重复
        PubCategoryExtDO query = new PubCategoryExtDO();
        query.setCategoryName(request.getCategoryName());
        List<PubCategoryDO> exists = pubCategoryMapper.selectListExt(query);
        if (!exists.isEmpty()) {
            throw new CommonException("910002", "类目名称已存在");
        }

        // 2. 构建插入对象
        PubCategoryDO insertPo = new PubCategoryDO();
        insertPo.setInternalKey(KeyGenerator.getInternalKey());
        insertPo.setCategoryCode("CATEGORY" + KeyGenerator.getInternalKey());
        insertPo.setCategoryName(request.getCategoryName());
        insertPo.setParentCode(request.getParentCode());
        insertPo.setSortOrder(request.getSortOrder() != null ? request.getSortOrder() : 0);
        insertPo.setSourceType("SYSTEM");
        insertPo.setCreateUser(request.getSysHead() != null
                ? request.getSysHead().getUserName() : "SYSTEM");
        insertPo.setGmtCreate(new Date());
        insertPo.setDelFlag("0");

        // 3. 保存
        int result = pubCategoryMapper.insert(insertPo);
        if (result <= 0) {
            throw new CommonException("910002", "类目管理表新增失败");
        }
        log.info("类目创建成功: {}", insertPo.getCategoryCode());
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void update(PubCategoryUpdateRequest request) {
        PubCategoryDO updatePo = new PubCategoryDO();
        updatePo.setCategoryName(request.getCategoryName());
        updatePo.setSortOrder(request.getSortOrder());

        // 使用 MpConditions 简化条件构建
        PubCategoryDO wherePo = new PubCategoryDO();
        wherePo.setInternalKey(request.getInternalKey());

        pubCategoryMapper.update(updatePo,
                io.github.openground.base.utils.MpConditions.whereOf(wherePo));
```

## 3.3 多数据源管理

框架提供统一的多数据源组件，支持配置式和表式两种数据源来源，以及 5 种数据库方言。

### 核心类

| 类 | 说明 |
|----|------|
| `DynamicJdbcTemplate` | 动态 JDBC 模板（执行 SQL、调用 Mapper、分页、事务） |
| `DynamicDataSourceManager` | 数据源管理器（懒加载、缓存、连接池管理） |
| `DataSourceProvider`（SPI） | 数据源提供者扩展接口 |
| `DbDialect`（接口） | 数据库方言（分页 SQL、元数据查询） |
| `DbDialectRegistry` | 方言注册表，按 dbType 自动路由 |

### 数据源来源

**方式一：配置式**（`ground.dblist`，启动时加载）

```yaml
ground:
  dblist:
    - dsName: master
      dbName: auth_db
      url: jdbc:mysql://localhost:3306/auth_db
      username: root
      password: 123456
      driverClassName: com.mysql.cj.jdbc.Driver
      dbType: mysql
```

**方式二：表式**（`sys_datasource` 表，按需加载）

通过 REST API `/sys/datasource/create` 或直接 INSERT 到 `sys_datasource` 表配置。密码使用 AES 加密存储，密钥通过以下配置项设定：

```yaml
ground:
  datasource:
    encrypt:
      key: ABCDEFG123456KEY
      iv: ABCDEFG1234567IV
```

**优先级**：`sys_datasource` 表(order=20) > `ground.dblist` 配置(order=10)，同名 dsName 表配置覆盖配置文件。

### 默认数据源优先级

`DynamicJdbcTemplate` 的无参方法（不指定 dsName 时）使用的默认数据源优先级如下：

1. **Spring Boot 主数据源**（`spring.datasource.*` 配置）— 最高优先级
2. **`ground.dblist` 配置的第一个数据源** — 兜底
3. **`sys_datasource` 表的第一个数据源** — 兜底

> 设计原则：`spring.datasource.*` 是业务主库，应作为默认数据源。`ground.dblist` 和 `sys_datasource` 是额外注册的动态数据源，需要通过 dsName 显式指定。

### 使用方式

```java
@Autowired
private DynamicJdbcTemplate dynamicJdbcTemplate;

// 1. 原始 SQL 执行（兼容 CLOB / NCLOB）
List<Map<String, Object>> result = dynamicJdbcTemplate.execSql(
    "master", "SELECT * FROM user WHERE id = 1", OperationType.SELECT);

// 2. 参数化查询（NamedParameterJdbcTemplate，推荐）
Map<String, Object> params = Map.of("name", "张三");
List<Map<String, Object>> users = dynamicJdbcTemplate.queryForList(
    "master", "SELECT * FROM user WHERE name = :name", params);

// 3. 无 dsName 时使用默认数据源（兜底 Spring 主数据源）
List<Map<String, Object>> list = dynamicJdbcTemplate.queryForList(
    "SELECT * FROM config", params);

// 4. DDL 执行
dynamicJdbcTemplate.executeDdl("master", "CREATE TABLE test (id INT)");

// 5. 存储过程调用
Map<String, Object> result = dynamicJdbcTemplate.execProcedure(
    "master", DynamicJdbcTemplate.getProcSql("mysql", "my_proc", "20260101"));

// 6. MyBatis Mapper 回调（类型安全，推荐）
User user = dynamicJdbcTemplate.executeWithMapper("business_db",
    UserMapper.class, mapper -> mapper.selectById(123));

// 7. Lambda 回调（灵活）
List<User> users = dynamicJdbcTemplate.executeInDataSource("business_db",
    session -> {
        UserMapper mapper = session.getMapper(UserMapper.class);
        return mapper.selectByCompany("ACME");
    });

// 8. 带事务的操作（异常自动回滚）
dynamicJdbcTemplate.executeInDataSourceTransactional("business_db",
    session -> {
        session.update("com.example.mapper.UserMapper.insert", user);
        session.update("com.example.mapper.LogMapper.insert", log);
        return null;
    });

// 9. 获取 Mapper 代理
UserMapper mapper = dynamicJdbcTemplate.getMapperInDataSource("db1", UserMapper.class);

// 10. 分页 SQL 生成
String pageSql = dynamicJdbcTemplate.handlePageSql("master", baseSql, 1, 20);
```

## 3.6 序列号 / ID 生成

### KeyGenerator 核心 API

```java
@Component
public class MyService {
    @Autowired
    private KeyGenerator keyGenerator;

    public void createOrder() {
        // 雪花算法 ID（Long 类型）
        Long id = keyGenerator.internalKey();

        // 格式化业务编码：ORD202501010001
        String orderNo = keyGenerator.businessKey("ORD", "ORDER_SEQ");

        // 纯数字序列
        Long nextKey = keyGenerator.nextKey("ORDER_SEQ");
    }
}
```

### 两种实现

| 实现 | 说明 | 配置要求 |
|------|------|---------|
| `Snowflake` + `KeyGenerator` | 53 位雪花算法，纯内存，不依赖数据库 | 无 |

## 3.7 对象存储 OSS

框架提供统一的文件存储抽象层 `OssClient` 接口，支持**本地文件存储**和**S3 协议对象存储**两种模式，通过配置即可切换，业务代码无需改动。

### 模式选择

| 模式 | 配置 | 说明 | 适用场景 |
|------|------|------|---------|
| **本地模式**（默认） | `type: local`（默认值，可省略） | 文件存储到本地磁盘，支持集群转发 | 开发测试、单机部署、无对象存储服务的环境 |
| **S3 模式** | `type: s3` + `enable: true` | 通过 AWS S3 协议兼容的对象存储 | 生产环境、阿里云 OSS / MinIO / 华为云 OBS |

### 本地模式

本地模式为默认模式，无需配置或简单配置即可使用。

#### 单机模式

```yaml
ground:
  oss:
    type: local                    # 默认值，可省略
```

文件默认存储到 `{user.dir}/../storage/default/` 目录（`bucketName` 默认 `default`）。

全量配置：

```yaml
ground:
  oss:
    type: local
    local:
      path: /data/app/storage     # 文件存储根路径（默认: {user.dir}/../fileStorage）
      # file-node-url:            # 不配置时为单机模式
```

#### 集群模式

集群模式下，所有节点使用同一份配置（如 Nacos 配置中心），通过 `fileNodeUrl` 指定文件节点，其他节点自动转发文件操作：

```yaml
ground:
  oss:
    type: local
    local:
      path: /data/app/storage
      file-node-url: http://192.168.1.100:8080/auth/uaa   # 文件节点完整地址
```

**节点角色判断**：`LocalOssClient` 启动时自动解析 `fileNodeUrl` 中的 IP，与本机 IP 比较：
- **IP 匹配** → 文件节点，直接读写本地磁盘
- **IP 不匹配** → 子节点，通过 HTTP 转发文件操作到文件节点

**文件节点 REST API**（自动注册，仅文件节点生效）：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/oss/file/upload` | POST | 上传文件（Multipart） |
| `/oss/file/download` | GET | 下载文件（流式返回） |
| `/oss/file/delete` | DELETE | 删除文件 |
| `/oss/file/list` | GET | 按前缀查询文件列表 |
| `/oss/bucket/create` | POST | 创建 Bucket（目录） |
| `/oss/bucket/remove` | DELETE | 删除 Bucket |
| `/oss/bucket/list` | GET | 列出所有 Bucket |

### S3 模式

S3 模式需要显式配置 `type=s3` 和 `enable=true`：

```yaml
ground:
  oss:
    type: s3                       # 必须显式指定
    enable: true                   # 必须启用
    endpoint: https://oss-cn-hangzhou.aliyuncs.com
    region: cn-hangzhou
    path-style-access: false
    domain: https://your-bucket.oss-cn-hangzhou.aliyuncs.com
    access-key: ${OSS_ACCESS_KEY}
    access-secret: ${OSS_ACCESS_SECRET}
    bucket-name: your-bucket       # 默认: default
    max-connections: 100
```

> 默认实现基于 AWS S3 SDK，兼容阿里云 OSS、MinIO、华为云 OBS 等 S3 兼容对象存储。

### 使用

```java
@Autowired
private OssClient ossClient;

public void upload(String bucketName, String objectName, InputStream stream) throws Exception {
    // 上传文件（本地模式下存到 {path}/{bucketName}/{objectName}）
    PutObjectResult result = ossClient.putObject(bucketName, objectName, stream);

    // 获取下载地址
    String url = ossClient.getObjectURL(bucketName, objectName);

    // 下载文件
    S3Object s3Object = ossClient.getObject(bucketName, objectName);

    // 删除文件
    ossClient.removeObject(bucketName, objectName);
}
```

> **注意**：业务代码面向 `OssClient` 接口编程，切换模式只需修改配置，代码无需改动。

## 3.12 通知消息推送（Notifier）

框架提供统一的通知消息推送组件 `Notifier`，通过 SPI 机制支持多渠道推送（站内信、钉钉、企微、邮件、短信等），实现业务系统与通知渠道的解耦。

### 设计目标

| 目标 | 说明 |
|------|------|
| **统一入口** | 业务系统只需调用 `Notifier.send()`，无需关心具体渠道的 API 差异 |
| **开箱即用** | Spring Boot 自动配置，引入依赖即可使用 |
| **灵活扩展** | 新增渠道只需实现 `NotifyChannel` SPI 接口 |
| **异步支持** | 内置 `@Async` + `CompletableFuture` 异步发送 |

### 核心接口一览

| 接口/类 | 包路径 | 说明 |
|---------|--------|------|
| `Notifier` | `common.notification` | 业务统一入口，提供 `send()` / `sendAsync()` |
| `NotifyChannel`（SPI） | `common.notification` | 通知渠道扩展接口，每个渠道一个实现 |
| `NotifyRequest` | `common.notification` | 业务请求 DTO（接收人、标题、内容、模板参数、指定渠道等） |
| `NotifyMessage` | `common.notification` | 标准化通知消息（渲染完成后分发给渠道） |
| `NotifyResponse` | `common.notification` | 发送结果聚合（各渠道成功/失败统计） |
| `NotifyMessageStore`（SPI） | `common.notification` | 站内信存储接口，业务方实现 |
| `NotifyTemplateRenderer`（SPI） | `common.notification` | 模板渲染引擎（默认实现 `DefaultNotifyTemplateRenderer`） |
| `SmsSender`（SPI） | `common.notification` | 短信发送器抽象（配合 SmsChannel 使用） |
| `InternalNotifyChannel` | `common-core` | 站内信默认渠道（通过 `NotifyMessageStore` 存储） |

### 使用示例

```java
@Autowired
private Notifier notifier;

// 1. 简单文本通知
notifier.send(NotifyRequest.builder()
    .receivers(List.of("zhangsan"))
    .title("审批提醒")
    .content("您有一条待审批的流程")
    .build());

// 2. 模板占位符通知（{{var}} 自动替换）
notifier.send(NotifyRequest.builder()
    .receivers(List.of("zhangsan"))
    .title("审批提醒")
    .content("您好，{{userName}}，申请单【{{businessKey}}】需要您审批")
    .templateParams(Map.of(
        "userName", "张三",
        "businessKey", "ABC123"
    ))
    .build());
// 实际发送: "您好，张三，申请单【ABC123】需要您审批"

// 3. 指定渠道发送
notifier.send(NotifyRequest.builder()
    .receivers(List.of("zhangsan"))
    .title("重要告警")
    .content("服务器 CPU 超过 90%")
    .channels(Set.of("DINGTALK", "SMS"))
    .build());

// 4. 异步发送
CompletableFuture<NotifyResponse> future = notifier.sendAsync(request);
future.thenAccept(response -> {
    log.info("发送完成: 成功{}, 失败{}",
        response.getSuccessCount(), response.getFailCount());
});

// 5. 带扩展参数（如钉钉链接）
notifier.send(NotifyRequest.builder()
    .receivers(List.of("zhangsan"))
    .title("审批提醒")
    .content("您有一条待审批的流程")
    .extras(Map.of("linkUrl", "http://portal.example.com/#/approval?taskId=123"))
    .build());
```

### 架构分层

```
业务系统调用 ──→ Notifier.send(NotifyRequest)
                      │
                      ├─ 1. DefaultNotifyTemplateRenderer 渲染 {{var}} 占位符
                      ├─ 2. 构建 NotifyMessage
                      ├─ 3. 确定目标渠道（指定/全部已启用）
                      ├─ 4. 逐渠道 send(NotifyMessage)，异常隔离
                      └─ 5. 聚合结果 → NotifyResponse
```

各渠道之间 **异常隔离**：一个渠道失败不会影响其他渠道；异步发送不阻塞调用线程。

### 配置项

```yaml
open-ground:
  notify:
    internal-enabled: true        # 站内信渠道开关（默认开启）
    async:
      core-pool-size: 4           # 异步线程池核心数
      max-pool-size: 8            # 最大线程数
      queue-capacity: 100         # 队列容量
```

# 4. Land 分布式调度框架

`open-ground-land` 是框架内置的分布式批处理调度框架，适用于定时任务调度、批量数据处理、ETL 作业等场景。

## 4.1 核心概念

## 4.6 架构特点

| 特点 | 说明 |
|------|------|
| **数据操作直连** | CRUD / 查询 / 状态更新直接本地执行，无需远程转发 |

|---------|---------|---------|

| **分离部署** | dispatch 直连中心库 | dispatch → HTTP → task 实例 |

# 5. 业务开发规范

本章参考 imap-pub 项目的实际开发实践，总结基于 open-ground 框架的行业务编码规范。

## 5.1 分层架构

```
Controller → Service → Mapper/Repository → Database
    ↓           ↓            ↓
   DTO       DO/Entity    XML Mapper
```

### 各层职责

| 层次 | 职责 | 约束 |
|------|------|------|
| **Controller** | 接收请求、参数校验、路由分发、响应返回 | 不写 try-catch；统一使用 `CommonResult` / `PaginatedResult`；使用 `@Operation` 注解生成 API 文档 |
| **Service** | 业务逻辑编排、事务管理、数据校验 | 定义接口 + 实现；`@Transactional(rollbackFor = Exception.class)`；使用 `@Slf4j` 日志 |
| **Mapper** | 数据访问、SQL 映射 | 继承 `BaseMapper<T>` 获得通用 CRUD |
| **DO** | 数据库表映射 | 字段与表列一一对应；包含审计字段 |
| **DTO** | 请求 / 响应数据传输 | 继承 `BaseRequest`；使用 Jakarta Validation 注解 |

### 审计字段（所有业务表必备）

### SQL 编写细则

- **禁止 `SELECT *`**，显式列出所有列
- 逻辑删除表始终带 `WHERE DEL_FLAG = '0'`
- 使用 MyBatis 动态 SQL（`<if>`、`<where>`、`<set>`、`<foreach>`）
- 分页使用 PageHelper，不手写 `LIMIT` / `ROWNUM`（多数据库兼容）

- 动态排序的 `${sort} ${order}` 在 Java 层做白名单校验
- 字段名避免使用数据库关键字（status、order、group、key、desc 等）

## 5.5 分页规范

统一使用 PageHelper 进行分页，返回 `PaginatedResult`：

```java
@PostMapping("/query")
public PaginatedResult<List<PubCategoryDO>> query(@RequestBody PubCategoryQueryRequest request) {
    // 1. 从请求头获取分页参数
    Integer pageNum = Optional.ofNullable(request.getAppHead())
            .map(AppHead::getPageNum).orElse(1);
    Integer pageSize = Optional.ofNullable(request.getAppHead())
            .map(AppHead::getPageSize).orElse(10);

    // 2. 设置分页（PageHelper ThreadLocal 方式）
    PageHelper.startPage(pageNum, pageSize);

    // 3. 执行查询（拦截器自动追加分页 SQL）
    List<PubCategoryDO> list = pubCategoryService.query(request);

    // 4. 封装分页结果
    PageInfo<PubCategoryDO> pageInfo = new PageInfo<>(list);
    return PaginatedResult.success(pageInfo.getList(), pageInfo.getPageNum(),
            pageInfo.getTotal(), pageSize);
}
```

## 5.7 DO / DTO 设计规范

### DO 实体

- 字段与数据库列一一对应，使用驼峰命名
- 基础审计字段在每个 DO 中都应有
- 如需要树形结构或关联查询字段，创建 `XxxExtDO extends XxxDO` 扩展类，不污染基础 DO

### 请求 DTO

- 所有请求 DTO 继承 `BaseRequest`
- 使用 Jakarta Validation 注解进行参数校验（`@NotBlank`、`@NotNull`、`@Size` 等）
- 不同操作（增 / 删 / 改 / 查）使用独立的 DTO，避免同一个 DTO 承载过多职责
- 每个字段加 `@Schema` 注解生成 API 文档（标注 `description`、`example`，必填字段设置 `requiredMode`）
- 类上加 `@Schema(description = "...")` 说明 DTO 用途

## 5.8 使用 MpConditions 简化 MyBatis-Plus 操作

`MpConditions.whereOf()` 可以将一个 DO 对象中的非空字段自动转为 `QueryWrapper` 的条件：

```java
import static io.github.openground.base.utils.MpConditions.whereOf;

// 删除：根据 DO 中的非空字段作为条件
pubCategoryMapper.delete(whereOf(deletePo));

// 更新：根据 wherePo 中的非空字段作为 WHERE 条件
PubCategoryDO updatePo = new PubCategoryDO();
updatePo.setCategoryName("新名称");
PubCategoryDO wherePo = new PubCategoryDO();
wherePo.setCategoryCode("CAT001");
pubCategoryMapper.update(updatePo, whereOf(wherePo));
```

## 5.9 Controller 规范

- **不接受 `@RequestParam` 单体参数**，一律使用 `@RequestBody` DTO 传入
- **不写 try-catch**，异常由全局 `GlobalExceptionHandlerControllerAdvice` 统一处理
- HTTP 状态码统一 200，通过 `CommonResult.code` 区分成败（遵循框架设计）
- 所有方法需标注 `@Operation` 注解（Swagger 文档）
- 类上标注 `@Tag` 注解，归类 API

## 3.13 通用权限服务（AuthCommonProvider）

通用权限服务 `AuthCommonProvider` 提供统一的用户权限、用户信息、字典、机构查询接口，根据部署模式自动切换实现。

### 接口定义

```java
public interface AuthCommonProvider {
    CommonResult<?> getuserFuncs(String userName);          // 获取用户功能权限
    CommonResult<?> getUserInfoByUserName(String userName); // 获取用户信息（含部门、角色）
    CommonResult<?> getUsersByUserNames(List<String> userNames); // 批量查询用户
    CommonResult<?> getDictByType(String dictType, String appName); // 获取字典
    CommonResult<?> listAllOrg();                          // 获取所有机构
}
```

### 两种实现

| 部署模式 | 实现类 | 所在模块 | 说明 |
|---------|--------|---------|------|
| `auth`（集成） | `LocalAuthCommonProvider` | `open-ground-common-core` | 通过 `NamedParameterJdbcTemplate` 直连主数据源 |
| `service`（微服务） | `FeignAuthCommonProvider` | `open-ground-common-springcloud` | 通过 `AuthFeignClient` 远程调用 Auth 服务 |

**自动装配规则**：框架通过 `@ConditionalOnAuth` / `@ConditionalOnService` 自动注入对应实现，业务方无需手动选择。

### 数据源说明

`LocalAuthCommonProvider` 使用 `NamedParameterJdbcTemplate`（Spring Boot 主数据源）查询认证相关表（`sys_user`、`sys_menu`、`sys_dict`、`sys_org` 等），`DynamicJdbcTemplate` 仅用于 `getDictByType` 中 `configType=1` 的动态外部表查询。

### 使用方式

```java
@Autowired
private AuthCommonProvider authCommonProvider;

// 获取用户功能权限
CommonResult<?> funcs = authCommonProvider.getuserFuncs("zhangsan");
Map<String, String> funcMap = (Map<String, String>) funcs.getData();

// 获取用户信息
CommonResult<?> user = authCommonProvider.getUserInfoByUserName("zhangsan");
Map<String, Object> userInfo = (Map<String, Object>) user.getData();

// 获取字典
CommonResult<?> dict = authCommonProvider.getDictByType("YOrN", "all");
List<Map<String, Object>> dictList = (List<Map<String, Object>>) dict.getData();
```

# 6. 二次开发与扩展指南

本章面向高级开发人员，介绍 open-ground 框架的 SPI 扩展机制和各模块的可扩展点。

## 6.1 部署模式扩展

框架支持两种部署模式，通过 `ground.mode` 配置切换：

```yaml
ground:
  mode: auth       # 集成模式（默认），直接 JDBC 操作数据库
  # mode: service  # 微服务模式，通过 Feign 远程调用认证服务
```

### 集成模式（auth）

所有操作在本地 JVM 完成。框架使用 JDBC 直接读写数据库表（如 session 表、操作日志表、序列号表），适合单体应用或简单微服务。

- `AuthCommonProvider` 使用 `LocalAuthCommonProvider` 直连主数据源
- `SequenceProvider` 使用 `JdbcSequenceProvider` 直连数据库
- `LogSender` 使用 `JdbcLogSender` 直写 `sys_opt_log` 表

### 微服务模式（service）

框架通过 Feign 远程调用认证服务完成 Token 校验、日志存储、序列号生成、通用权限查询等操作。需要部署独立的认证服务（`ground-auth`）。通过 `open-ground-common-springcloud` 模块的 Feign 客户端实现。

- `AuthCommonProvider` 使用 `FeignAuthCommonProvider` 远程调用 Auth 服务
- `SequenceProvider` 使用 `FeignSequenceProvider` 远程获取序列
- `LogSender` 使用 `FeignLogSender` 远程写入日志

## 6.2 SPI 扩展机制

框架大量使用 SPI 接口进行功能扩展。以下是所有可扩展点：

### 完整 SPI 清单

| `LogSender` | common-api | `JdbcLogSender`（本地）/ `FeignLogSender`（远程） | 操作日志发送 |
| `DataSourceProvider` | common-core | `ConfigDataSourceProvider`（配置式）/ `SysDatasourceProvider`（表式） | 自定义数据源来源 |
| `OssClient` | common-core | `S3OssClient` | 对象存储客户端 |
| `DictTranslator` | common-api | 无（默认不翻译） | Excel 字典翻译 |

### 扩展示例：自定义模板引擎（如 FreeMarker）

实现 `NotifyTemplateRenderer` 接口替换默认的 `{{var}}` 渲染器。组件通过 `@ConditionalOnMissingBean` 自动使用业务方的实现：

```java
@Component
public class FreeMarkerTemplateRenderer implements NotifyTemplateRenderer {
    private final Configuration freemarkerConfig;

    public FreeMarkerTemplateRenderer() {
        this.freemarkerConfig = new Configuration(Configuration.VERSION_2_3_32);
        this.freemarkerConfig.setTemplateExceptionHandler(
            TemplateExceptionHandler.RETHROW_HANDLER);
    }

    @Override
    public String render(String template, Map<String, Object> params) {
        if (template == null) return null;
        if (params == null || params.isEmpty()) return template;
        try {
            Template tpl = new Template("notify", new StringReader(template),
                freemarkerConfig);
            Writer out = new StringWriter();
            tpl.process(params, out);
            return out.toString();
        } catch (Exception e) {
            throw new NotifyException("模板渲染失败", e);
        }
    }
}
```

## 6.3 自动配置原理

框架所有功能模块使用 Spring Boot 3.x 的 `@AutoConfiguration` + `META-INF/spring/*.imports` 进行自动装配。

```java
// 配置类示例
@AutoConfiguration
@ComponentScan(basePackages = "io.github.openground.base")
public class BaseAutoConfiguration {
}
```

```properties
# META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
io.github.openground.base.config.BaseAutoConfiguration
```

这种设计实现了"引入即用"——业务项目只需要添加 Starter 依赖，无需手动 `@ComponentScan` 或 `@Import`。

### 模块自治原则

| 模块 | 自动装配类 | 扫描范围 |
|------|-----------|---------|
| `open-ground-base` | `BaseAutoConfiguration` | `io.github.openground.base` |
| `open-ground-common-core` | 11 个 AutoConfiguration | 各自功能包 |
| `open-ground-common-springcloud` | 5 个 AutoConfiguration | Feign 远程实现 |
| `open-ground-security-core` | `SecurityAutoConfiguration` | `io.github.openground.common.security` |
| `open-ground-land-core` | 4 个 AutoConfiguration | Land 调度引擎 |
| `open-ground-land-dispatch` | `LandDispatchAutoConfiguration` | 调度中心 |

每个模块各自管理自己的自动配置，引入即用，不跨模块扫描。

## 6.5 新增数据库方言

```java
@Component
public class KingbaseDialect implements DbDialect {
    @Override
    public String getDbType() { return "kingbase"; }

    @Override
    public String getLimitSql(String sql, int offset, int limit) {
        return sql + " LIMIT " + limit + " OFFSET " + offset;
    }

    @Override
    public String getTableListSql(String schemaName) {
        return "SELECT table_name FROM information_schema.tables ...";
    }

    @Override
    public String getColumnListSql(String schemaName, String tableName) {
        return "SELECT column_name, data_type FROM information_schema.columns ...";

    }
```
